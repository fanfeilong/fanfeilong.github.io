# 灰库 · Fan Feilong

首页直接显示灰库。左侧是知识分类，顶部右侧是博客园、知乎、笔记、随笔与 GitHub 链接。站点发布到 `https://fanfeilong.github.io/`。GitHub Pages 只需要构建出的静态文件；整理标记由本地 Python 后端提供。

## 本地整理（推荐先用这个）

需要 Node.js 22.13+、npm、Python 3.10+。使用 `.nvmrc` 可选择 Node 22。

```sh
npm ci
npm run local
```

打开 http://127.0.0.1:8765/ 即进入灰库。旧 `/books/book-manager/` 地址会保留查询参数并跳转到首页。如果端口冲突，先 `npm run build`，再 `python3 books/book-manager/server.py --port 8766`。

- PDF、Markdown、Word、PowerPoint、图片等全部灰库资料均有“保留 / 不要 / 重置”操作。
- 用“未标记 / 保留 / 不要”筛选整理状态，也可叠加分类、主题、搜索与文件格式筛选。
- “不要”只记录选择，**不会删除原文件**。顶部显示待释放大小，可导出 JSON 清单。
- 标记保存到 `~/.local/state/fanfeilong-library/<仓库路径标识>.json`，重启服务后仍在；不会进入仓库或 Pages 制品。终端会打印实际位置。
- 每条标记包含文件路径、大小、修改时间和 SHA-256。文件变化时旧标记失效，回到“未标记”，需要重新确认。
- 完成一轮后，让维护者根据本地清单核验并移除“不要”的原文件，再重建站点。本项目目前没有删除 API，也不会自动清理源文件。
- 后端仅监听 `127.0.0.1`。测试时可用 `--state-file /某个临时目录/reviews.json` 隔离标记记录。

## 公开静态模式

```sh
npm run build
npm run preview
```

打开 http://127.0.0.1:4173/ 。公开模式没有整理按钮，也不依赖 Python API；收藏、最近阅读和 PDF 页码仅保存在访客当前浏览器。PDF 使用随站点打包的 PDF.js，其他格式使用原文件链接，是否可直接预览取决于浏览器。PDF 画布阅读器没有完整文字层，可下载原 PDF 交给系统阅读器使用搜索、复制与辅助阅读功能。

构建器 `scripts/build.py` 扫描 `books/` 实体资料与旧站根目录的 PDF / Office 文件，生成 `books/book-manager/books.json`，并打包首页和阅读器所需资源。灰库源码、开发依赖、本地标记和测试产物不会发布。专题旧页、播放器与工具下载及其专用资源已移除；当前书目中的保留资料仍正常发布。

新增书籍放入 `books/NN_领域/NN.MM_主题/`，重建后自动出现在主页与灰库。`books/分类索引.md` 是历史手工索引，页面数量以实时扫描为准。构建会拒绝 >=100 MiB 的单个灰库文件和 >=1 GB 的站点制品。

## 资源链接与分享

每份登记的资源都有真实静态入口，例如 `/read/linux-internals/`；`?page=6` 表示 PDF 的第 6 页（与顶部 `n / m` 一致，不是书内印刷页码）。直接打开和刷新均可接续该页，显式页码优先于本地进度；未指定时恢复当前浏览器的进度。无效页码回到第 1 页，超出总页数时限制到末页。

阅读器顶部的链接图标复制当前页的链接；浏览器拒绝复制时会显示可手动复制的输入框。翻页成功后更新地址，不重新加载文档，也不增加逐页的后退记录。浏览器后退可回到打开资源前的页面。

`books/book-manager/resources.json` 保存资源固定 ID 与文件路径的对应关系。移动或改名已有文件时，**只修改该条目的 path，保留 id**；删除资源时保留登记条目，构建会留下说明资源不可用的页面。新文件运行 `python3 scripts/build.py --sync-resources` 登记一次，并将更新后的 JSON 提交；已有 ID 不会重新分配。

构建为每份资源生成 `dist/read/<id>/index.html`，包含书名、描述、canonical 与 Open Graph 元数据，并复用原始文件和同一阅读器。JS/CSS 使用带内容指纹的文件名，目录 JSON 的请求也带构建版本，减少新页面与旧缓存混用。普通刷新会按新 HTML 引用相应资源；已打开且未重新加载的旧标签不会自动升级。

## 课程与仓库技能

左侧“课程”目录来自 `books/07_课程/<主题>/`。每门课程是一份 `course/v1` Markdown：JSON 兼容的 YAML front matter 保存课程号、机构、教师、届次、工作量、来源与核实日期，正文按固定章节记录课表、考核、资源和信息缺口。未知信息使用 `null`，不把公开材料推定为免费报名或有证书。课程 Markdown 会在构建时渲染为真实静态阅读页，原始 Markdown 仍可下载。

示例是 `books/07_课程/数字制造/mit-htmaa-2026.md`，阅读入口为 `/read/mit-htmaa-2026/`。课程卡片支持按英文名称、机构、课程号、教师和主题搜索。原始 HTML 在 Markdown 渲染中被禁用，链接保留 markdown-it 的危险协议检查。

仓库技能保存在 `skills/`。运行：

```sh
make install
```

会安装到**本仓库** `.codex/skills/`，不会写入全局技能目录。重复安装更新本安装器管理的同名技能，保留其他技能；遇到未由本安装器管理的同名目录会停止，不覆盖它。生成的安装副本已加入忽略列表，维护源文件应修改 `skills/`。

第一个技能为 `$import-course`，例如：

```text
$import-course https://pub.cba.mit.edu/863.26/site/
```

该技能核对官方课程信息、按规格生成或更新课程 Markdown，再校验与构建；辅助命令和字段规则见 `skills/import-course/SKILL.md` 及其 `references/course-schema.md`。新条目通过 `python3 scripts/build.py --sync-resources` 登记固定 ID；更新保持 ID 和个人“学习记录”。创建课程与安装技能不会自动提交或发布。

## PDF 移动阅读

- 顶部始终显示当前页码 `n / m`。翻页、缩放和阅读设置默认收起，点击顶部设置图标展开或收起；设置面板浮在正文上方，切换不会挤动页面。每次打开 PDF 时重新收起。
- 手机默认使用“正文适宽”，按页面上的文字与图形检测白边；自动裁边保留安全间距，左右最多各裁 15%、上下最多各裁 10%。扫描页的阴影、边框可能限制自动效果。
- “裁边”可额外裁去左右各 0–12%；“还原整页”恢复原始版面、缩放和整页阅读。原 PDF 不会被修改。
- 双击或触屏双点放大当前位置；双指缩放、触摸板捏合，以及工具栏加减按钮可调节到适宽比例的 50–500%。缩放时先预览，结束后重新渲染，并限制 Canvas 像素量。
- “双栏阅读”按左栏 → 右栏 → 下一页左栏依次浏览，适合双栏论文；它是手动开启的版面切分，跨栏图表请切回整页查看。
- 鼠标拖动或触屏向左 / 向上翻到下一页，向右 / 向下返回上一页。长页、放大后的页面优先拖动浏览，到边缘后另起一次手势再翻页。
- Mac Edge 触摸板双指滚动也可翻页：滚动方向向右 / 向下（页面内容向左 / 向上）为下一页，反方向为上一页。同一轮衰减惯性只翻一页；明确反向、惯性衰减后的新一拨滑动，或短暂停顿后的独立滑动可继续翻页。有可滚动内容时优先滚动。
- 翻页同时检查距离与速度，支持短促快划；渲染期间保留最新一次独立翻页意图，完成后再执行，避免丢手势或累积惯性连翻。关闭阅读器时清除待执行意图。
- 可用 `PLAYWRIGHT_CHANNEL=msedge npm test` 在已安装的 Microsoft Edge 中运行同一套测试；触摸板测试发送浏览器滚轮事件，不等同于物理触摸板真机操作。

## GitHub Pages 发布

发布流程由 `.github/workflows/pages.yml` 管理，`master` 推送后自动构建、测试并部署。Pages 的发布源使用 **GitHub Actions**。后续更新时：

1. 完成资料整理，核验后移除不再保留的源文件。
2. 首次启用或迁移仓库时，确认 Settings → Pages → Build and deployment → Source 为 **GitHub Actions**。
3. 将需要发布的改动和书籍提交并推送到 `master`。
4. `.github/workflows/pages.yml` 自动安装依赖、生成静态站点、运行测试，再部署到 Pages；PR 只验证、不部署。
5. 确认 Actions 的 deploy 成功，再检查线上主页、中文书名链接和 PDF 阅读。
